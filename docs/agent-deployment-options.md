# Agent deployment options for Monadator

Research checked against official documentation on September 12, 2026. Recommendations below are judgments about this repository's requirements; deployment speed and total cost have not been benchmarked.

**Recommendation:** shortlist Railway for a public web demo and Modal for a Python agent that runs on demand. Keep the decision engine runnable locally so cloud deployment also preserves the hackathon submission contract. Choose LangSmith Deployment when persistent agent workflows become a product requirement.

The repository's `README.md` and `problem_statement.md` describe a batch workload: process 250 requests from CSVs and supporting images, simulate 90 days of finances, and generate `output.csv`. They require a terminal entry point, a runnable code package, a transcript, and `evaluation/usage_report.md`. They do not require a hosted website. At inspection, `code/main.py` was empty, so there is an implementation step before anything useful can be deployed.

An agent launch involves several choices: the model API, your code and workflow, the host that executes it, and the interface people use. A hosting platform can execute your financial engine while you independently choose the model used to interpret messages and images. An agent platform adds facilities such as saved workflow state and run inspection.

**If you mean a platform for assembling the agent itself**, Dify and n8n also merit a look. Dify publishes its apps as REST APIs and supports agent, chat, and workflow app types. n8n offers hosted workflows, integrations, code steps, and webhook triggers; its advertised Starter price is €20/month billed annually for 2,500 workflow executions. For this challenge, my preference is to have those workflows call a reusable Python financial engine so the terminal submission stays straightforward. [Dify API](https://docs.dify.ai/en/api-reference/guides/get-started), [n8n plans](https://n8n.io/pricing/)

**A concrete launch path for this repository:**

1. Implement one reusable decision function and a CLI that reads `dataset/` and writes the required root-level `output.csv`.
2. Use the model to extract structured facts from relevant messages and images. Keep the cash-flow forecast, payment arithmetic, plan ranking, and safety checks in deterministic code.
3. Validate against the public solved examples, then run the evaluation requests. Capture model names, calls, token counts, and estimated cost for the final run in `evaluation/usage_report.md`.
4. For a web demo, add a small API and a page where a visitor selects a request and sees the recommendation, evidence, and payment schedule. Deploy that application on Railway. Reuse the same decision function as the CLI.
5. For a full-dataset web action, submit a background job and return a job ID. Show progress and a download link when complete. Modal documents this submit/poll pattern directly. [Job processing](https://modal.com/docs/guide/job-queue)
6. Save outputs and usage reports outside temporary container storage, with separate paths per run. Modal offers persistent Volumes; Railway offers mounted volumes. Cloud Run's local filesystem disappears when the instance stops, so export results to durable storage before exit. [Modal Volumes](https://modal.com/docs/guide/volumes), [Railway volumes](https://docs.railway.com/volumes), [Cloud Run filesystem](https://docs.cloud.google.com/run/docs/container-contract)

For a first launch, choose one host and add other infrastructure when a concrete requirement warrants it. Railway can host the first application; Modal can host both the API and its Python jobs. They are alternatives here, not a mandatory two-platform stack.

Treat quoted prices as hosting baselines. Model API calls, databases, storage, networking, and tracing can add costs. Total cost cannot be estimated responsibly until the implementation's actual model calls, tokens, and runtime are measured. Do not rent a GPU solely to call an external model API.

This research did not create cloud resources, deploy an application, or validate a running service.
