## Current executable interfaces

- `buy_wait.data.Dataset.load(dataset_root)` reads **only** the six supporting CSVs listed in `CONTEXT_FILES`. `load_requests(dataset_root)` separately reads the eight-field production request file. Both return/source-pin immutable source-string rows, not financially admitted Money. Fixed-name allowlists, exact headers, record widths, duplicate IDs, same-user event links, lifecycle cycles and dated/directed duplicate FX keys are checked. Symlink CSVs are rejected before reading. Numeric admission belongs to core, not a competing converter in the loader.
- `Dataset.context_for(request)` returns an immutable **raw input envelope** with `request`, `profile`, `events`, `options`, `fx_rates`, `message_candidates`, `image_candidates`, `source_locations`, `source_hashes`. Requests are projected using exactly the eight allowed input fields. Missing event amounts stay `""`, never zero. User-scoped candidates include unlinked and event-only sources. These are candidates, not admitted evidence: extraction still owns optional-ID matching, timestamps/as-of filtering and image bytes. Images need not exist for raw metadata inspection to pass.
- **Authoritative typed planning adapter:** `Dataset.planning_context_for(request) -> buy_wait.data.PlanningContext`. Its frozen `RequestInput` has exactly the eight input fields: IDs/type/text as strings, dates as `date`, partial permission as `bool`, amount as the **real core Money**. `PlanningPreferences` exposes `.methods`, `.max_installment_months` (blank → `None`), `.protected_categories`, `.reducible_categories`, `.stoppable_categories`, `.financial_priorities`; method/category collections are immutable whole tokens, never substring matching. `SuppliedOption` preserves the nine provider columns, parsing dates/counts/optional interval and the three monetary fields through core. Late/unaccepted offers are retained for planning to reject, not silently dropped. The envelope provides immutable `.options_by_id`, `.request`, `.preferences`, and `.context_hash`; options are stored once in stable ID order, and the core's canonical hasher hashes typed request/preferences/options. No Plan/PlanValidation/result clone is introduced.
- **Actual narrow core adapter:** `Dataset.financial_input_for(request, evidence_sources=()) -> buy_wait.contracts.FinancialInput`. It constructs the imported `FinancialProfile`, `EventRecord`, `FxRate` and CSV `SourceRef` records; delegates cent-exact/optional Money parsing to `buy_wait.core.money`; leaves unknown amounts/dates `None`; and does not perform FX conversion, cash classification or a forecast. The core view excludes offers, deadlines, payment methods/caps, partial permission and request text. Its admitted profile carries only financial balances and category protection/adjustability. Extraction's host-built message/image SourceRefs can be supplied after selection; no guessed `known_at`, actor, hold, settlement or image cash is synthesized. CSV source IDs are `csv:<filename>:<business-id>`; FX business IDs are `<date>:<from>:<to>`. Paths are relative to `dataset/`, record ordinals exclude the header, and a CSV source hash is the parsed file hash.
- `Dataset.source_location(table, indexed_row)` and raw `.source_locations["message:<id>"|"image:<id>"]` expose immutable `{relative_path,row_number,csv_sha256}` locators so evidence need not reparse CSV or mistake a filtered-user index for a file record ordinal. **`csv_sha256` is not the decoded image/text leaf hash**; evidence computes the latter and source availability itself.
- `evaluation.samples.load_sample_fixtures(dataset_root)` is harness-only: 15 source columns become separate input and expected-output tuples. `evaluate_samples(dataset_root, decide, audit=None)` calls the supplied **trusted committed composition** with only the raw context; expected fields are joined afterward. There is no model, sample lookup, fallback classifier or dynamically selected CLI plugin inside this harness. It records missing/failed rows and sanitized exception classes rather than reporting a partial denominator as complete.
- `evaluation.metrics.compare_predictions(...)` keeps amount signed/absolute errors by home currency, normalized amount error, blank/date confusion and signed/absolute date errors, status/method confusion plus joint agreement, normalized schedule/action reference agreement and structural defects separate. No hidden weights are invented. Literal explanation match is not used. Real safety, schedule eligibility, action validity and grounding require a supplied audit adapter; missing evidence is explicitly `not_checked`, not a passing financial verdict. Error records start open; a detector does not invent a financial root cause, fix or regression ID.
- `evaluation.samples.persist_run(...)` creates a new run directory exclusively, retaining predictions (raw JSON and the exact eight-column CSV projection), metrics, per-request results, errors, failures and a summary. A hash manifest is written last; interrupted attempts without it remain incomplete. Existing run IDs and dataset destinations are refused. Expected fixture hashes are harness metadata, not inference evidence. Configuration supplied here must contain no secrets.
- `buy_wait.output.structural_issues(row, request)` checks the exact eight fields, enums, decimal/date/action grammar, bounds, partial two-payment arithmetic, basic installment sums, deadlines/horizon and status consistency. It is **not** supplied-option matching, preference/protection validation, balance replay or grounding. `write_output(..., dataset_root=...)` checks all structural rows before atomic replacement, enforces coverage/uniqueness/input order, preserves CSV quoting and refuses dataset paths. A future final runner must first obtain complete core/planning certification. A zero request does not acquire an invented positive payment minimum.

`python3 code/main.py --check-inputs` and `python3 code/evaluation/main.py` are read-only inspection commands. `python3 code/evaluation/main.py --predictions <public-development.csv> --run-id <new-id>` compares an existing development CSV; it performs no model or financial replay. Real-data checks remain input, selection, decode and support-validation tests, not a complete decision evaluation. Baseline/iteration inference and full trace diagnosis remain to be executed once the complete composition exists.
